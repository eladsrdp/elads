# קליטת הודעות WhatsApp (Inbox Capture) — עיצוב

## הקשר

בשלב 1 של פרויקט הסוכן האישי בוואטסאפ (ראה [[whatsapp-personal-agent]] ב-vault) קיבל Claude יכולת **לשלוח** הודעות WhatsApp דרך מופע WAHA שרץ בעצמו (שרת Hetzner, `188.245.198.72`), עם המספר האישי של המשתמש מקושר. המסמך הזה מכסה את החלק הראשון של שלב 2: **קליטת הודעות נכנסות** מצ'אט ייעודי אחד — בלי שום לוגיקת תגובה עדיין. מה עושים עם ההודעות שנקלטו זה במפורש **לא** בתחום המסמך הזה — זה יוחלט בהמשך, בנפרד.

שלב 2 פוצל מבקשה גדולה אחת ("סוכן שיחתי + Outlook + חשבוניות") לתת-פרויקטים עצמאיים (ראה Open Questions בטופיק ה-vault). זה תת-פרויקט #1 מהפיצול הזה, שצומצם עוד יותר במהלך ה-brainstorming לקליטה בלבד, לפי בקשת המשתמש.

## מטרה

לקלוט בצורה אמינה כל הודעה (טקסט וקול) שנשלחת אל/מ צ'אט WhatsApp ייעודי אחד — "הודעה לעצמי" (`972542438624@c.us`) — לתוך מאגר נתונים ניתן-לשליפה, על אותו שרת שבו כבר רץ WAHA. בלי תגובה אוטומטית, בלי תמלול, בלי חשיפה לאינטרנט.

## מה בכוונה לא נכלל (Non-goals)

- החלטה מה לעשות עם ההודעות שנקלטו (לוגיקת תגובה, "מוח" הסוכן) — מסמך עיצוב נפרד בעתיד.
- תמלול הקלטות קול או הורדת קובצי שמע — תת-פרויקט #2 בעתיד. הודעות קוליות נרשמות רק כמטא-דאטה.
- אינטגרציית Outlook, זרימת חשבוניות — מסמכים נפרדים בעתיד, לא מושפעים מהשינוי הזה.
- קליטה מכמה צ'אטים — רק הצ'אט הייעודי האחד בתחום.

## ארכיטקטורה

שירות חדש, `inbox`, מתווסף כ-container שני ב-`waha/docker-compose.yml`, לצד שירות ה-`waha` הקיים, על אותו שרת Hetzner. הוא יושב **רק** ברשת הדוקר הפנימית — בלי פורט חשוף למארח (host) או לאינטרנט הציבורי, בהתאמה לעמדת האבטחה הקיימת (WAHA עצמו חשוף רק ל-`127.0.0.1`).

```
WhatsApp (צ'אט לעצמי) → WAHA (מנוע NOWEB) → [POST פנימי בדוקר] → שירות inbox → SQLite
```

`WHATSAPP_HOOK_URL` ב-WAHA יוגדר ל-`http://inbox:8080/webhook` (שם DNS פנימי של דוקר, לא כתובת ציבורית). `WHATSAPP_HOOK_EVENTS` נשאר `message`.

שירות ה-`inbox` הוא אפליקציית Hono + TypeScript קטנה (תואמת למוסכמות הקיימות בריפו כמו `priority-lite/server` ו-`hachamama-parenting-program/server`), עם `better-sqlite3` לאחסון. הוא חושף נתיב אחד בלבד: `POST /webhook`.

## זרימת מידע

1. הודעה נשלחת אל/מ הצ'אט הייעודי. WAHA מפעיל אירוע webhook מסוג `message` ל-`inbox`.
2. `inbox` בודק שסוג האירוע הוא `message` וש-chat id תואם למשתנה הסביבה `SELF_CHAT_ID` (`972542438624@c.us`). כל צ'אט אחר נדחה (מוחזר 200 OK, בלי שמירה) — זו לא שגיאה, רק סינון רעש.
3. `direction` נגזר מהשדה הבוליאני `fromMe` בפיילוד (`true` → `outgoing`, `false` → `incoming`) — שני הכיוונים נקלטים כי זה צ'אט לעצמי.
4. סוג ההודעה נקבע מהשדה `type` בפיילוד של WAHA:
   - טקסט (`chat`) → שומר את `body` כמו שהוא.
   - הודעה קולית (`ptt`) → שומר עם `type=voice`, `body=NULL`. קובץ השמע **לא** מורד בשלב הזה בכלל.
   - כל דבר אחר (תמונה, מסמך וכו') → שומר עם `type=other`, `body=NULL`, הפיילוד המלא נשמר ב-`raw_json` לשימוש עתידי.
5. נכתבת שורה בטבלת `messages` (סכמה למטה), כולל ה-JSON המלא של ה-webhook לגמישות עתידית.
6. `inbox` מחזיר `200` מהר.

## מודל הנתונים

קובץ SQLite על Docker volume בשם (`inbox_data:/app/data/inbox.db`), באותו דפוס התמדה כמו `waha_sessions`.

```sql
CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  waha_message_id TEXT NOT NULL UNIQUE,
  direction TEXT NOT NULL CHECK (direction IN ('incoming', 'outgoing')),
  type TEXT NOT NULL CHECK (type IN ('text', 'voice', 'other')),
  body TEXT,
  timestamp INTEGER NOT NULL,
  raw_json TEXT NOT NULL,
  received_at INTEGER NOT NULL
);
```

`waha_message_id` הוא unique כדי שמשלוח webhook כפול (WAHA עושה retry על תשובות שאינן 2xx) לא ייצור שורה כפולה — ה-insert נכשל בשקט בהתנגשות (`INSERT OR IGNORE`).

## טיפול בשגיאות

| מצב | התנהגות |
|---|---|
| פיילוד לא נפרס / מבנה לא מוכר | לוג, מחזיר `200` (לא רוצים לגרום ל-WAHA להיכנס ל-retry storm על משהו ש-retry לא יפתור) |
| chat id לא תואם ל-`SELF_CHAT_ID` | מחזיר `200`, בלי שמירה (רעש צפוי, לא שגיאה) |
| כשל כתיבה ל-DB (למשל דיסק מלא) | מחזיר `500` — WAHA מנסה שוב לפי מדיניות ה-retry שלו, ההודעה לא הולכת לאיבוד בשקט |
| `waha_message_id` כפול | ה-insert מתעלם (unique constraint), עדיין מחזיר `200` |
| קריסת השירות | `restart: unless-stopped` על ה-container (כמו לשירות `waha`) מרים אותו אוטומטית |

## בדיקות

Vitest, עם `app.request()` של Hono ישר על נתיב ה-webhook (אותו דפוס כמו ב-`priority-lite/server`), בלי תלות ב-WAHA אמיתי או ברשת:

- פיילוד הודעת טקסט מהצ'אט הייעודי → שורה מופיעה ב-`messages` עם `type=text` ו-`body` נכון.
- פיילוד הודעה מצ'אט **אחר** → לא נכתבת שורה, התשובה עדיין `200`.
- פיילוד הודעה קולית (`ptt`) מהצ'אט הייעודי → שורה מופיעה עם `type=voice`, `body=NULL`.
- אותו `waha_message_id` נשלח פעמיים → נשארת רק שורה אחת אחרי שני הבקשות.
- פיילוד לא תקין (שדות חסרים) → התשובה `200`, בלי קריסה, בלי שורה שנכתבת.

בדיקה חיה מול WAHA האמיתי (שליחת הודעת בדיקה בפועל ואימות שהיא נכתבה לקובץ ה-SQLite ב-SSH) תיעשה ידנית בזמן הפריסה, כמו בהקמת WAHA בשלב 1 — לא חלק מחבילת הבדיקות האוטומטיות.

## מה נדחה בכוונה (מתועד כ-Open Questions ב-[[whatsapp-personal-agent]])

- מה עושים עם ההודעות שנקלטו (לוגיקת תגובה, "מוח" הסוכן) — תת-פרויקט לעיצוב בהמשך.
- תמלול הקלטות קול ושליפת קובצי שמע — תת-פרויקט #2.
- האם `inbox` יצטרך אי-פעם להיות נגיש מחוץ לרשת הדוקר (ידרוש הוספת אימות `WHATSAPP_HOOK_HMAC_KEY`) — לא נדרש בתחום הזה.
